# INITIALIZATION
- create.sh를 수행하면 contents.md와 materials 디렉토리가 생성된다. 
  - contents.md에는 장절을 갖춘 샘플 양식을 추가해준다.  (타이틀 포함하여 5장 정도 포함, 필요시 세부 장에 대한 구분 슬라이드도 포함)
  
# INSTRUCTION
- 사용자가 직접 작성한 contents.md를 기반으로 작성한다.
  - contents.md에는 장절로 나누어져있고, 문단 단위로 압축하여 한 문장 정도로 작성한다.
- contents.md를 작성하였으면 클로드에 "컨텐츠 제작"를 지시하면 클로드는 contents.md를 기반으로 slide.md와 review.md를 작성한다.
- contents.md를 기반으로 클로드는 발표자료 내용을 slide.md로 작성한다.
  - 발표자료의 디자인은 design/mydesign.md를 기반으로 작성된다.
- 발표 내용에서 부족한 부분은 review.md 에 작성한다.
  - 발표 내용에서 부족한 부분을 명시적으로 지적한다.
  - 전체적으로 논리적이지 않은 부분을 지적한다.
  - 보완할 사항에 대해 명시적으로 작성한다.

## PRESENTATION DESIGN
- 발표자료의 디자인은 design/mydesign.md를 사용한다.
- 발표자료 내용은 slide.md에 마크다운 형태로 작성한다.
  - 수식, 표, 및 그림/동영상은 동일하게 포함시킨다.
- 발표자료는 html로 작성하고 pdf로도 생성한다.
- instruction.md와 contents.md 파일을 항상 확인한다.
  - CLAUDE.md, intruction.md 및 contents.md는 CLAUDE가 직접 수정할 수 없다.
- 변경 사항이 있는지 확인하고 변경 사항이 발생하면 업데이트 한다.
- 타이틀은 가급적 영어로 작성한다. 
- 그림, 수식, 테이블 등은 열과 오를 맞추어서 배치한다.
- 수식에서는 번호를 추가하되 번호는 오른쪽으로 정렬한다.
  - 수식에 각 항목에 대해서 구분하여 설명하도록 한다.
  - 수식 바탕은 투명색으로 유지한다.
- 정리 슬라이드는 없다.
- 구어체 사용하지 말것 . 형식을 갖춘 개조식 사용
  - 예: "지금 이 세 줄만 확인되면 오늘 하루가 편해진다"
  - 예: 슬라이드는 웹에 그대로 올라가 있다. 지금 바로 열어 두면 된다
  - 예: "지금 이 세 줄만 확인되면 오늘 하루가 편해진다"
  - 예: "문제 — 조교 노트북에서 되는 코드가 내 노트북에서 빌드조차 안 된다."

## REVIEW
- 전체 구조가 잘 맞는지 확인한다.
  - Introduction, Related Works, Problem Definition, Proposed Method, Experiments, Conclusion
- 논리적으로 허점이 있는지 확인한다.
- 너무 글이 많이 적혀 있는지 확인한다. (간단 명료하게 글이 작성되도록 해야 한다.)
- 전체 내용을 설명한 큰 그림이 있는지 확인한다.
- 전체적은 스토리가 살아 있는지 확인한다.
- 실험 결과로 그래프 및 테이블이 있는지 확인한다.
- 실험 결과에 대한 비교 대상이 있는지 확인한다.


# DISTRIBUTION
- 배포시 필요 데이터 및 결과물은 output 폴더에 위치한다.
- pdf 뿐만 아니라 html, 이미지 동영상등이 여기에 포함되어야 한다.
